## Catálogo público SEC / EcoCarga en vivo

- Se añadió el endpoint `GET /api/estaciones/sec`, que consulta la fuente oficial `https://cargadorespublicos.cl/api/data` mediante el backend y almacena la respuesta en caché durante dos minutos.
- La fuente es la plataforma pública de interoperabilidad de la SEC/EcoCarga. Para cada ubicación se entregan dirección, comuna, región, coordenadas, folio IRVE, horario declarado, operador y última actualización.
- Cada ubicación incorpora los equipos de carga declarados: marca, modelo, referencia física, potencia, estado, simultaneidad y el detalle de cada conector (estándar, AC/DC, potencia y estado).
- El catálogo de red de carga permite seleccionar un vehículo y calcula la compatibilidad utilizando sus conectores registrados. La UI muestra explícitamente los conectores compatibles o indica que no existe compatibilidad.
- La disponibilidad se informa tal como llega desde SEC: `DISPONIBLE`, `OCUPADO`, `NO DISPONIBLE` o `FUERA DE LINEA`, junto con sus conteos y fecha de actualización. No se infiere disponibilidad cuando la fuente no la reporta.
- Se verificó una consulta real para **Electrolinera ENEX Portugal 175 Santiago**: dirección `Portugal 175, Santiago, Metropolitana`, equipo `ABB TERRA 54 CJT`, estado `DISPONIBLE` y compatibilidad CCS2 para Tesla Model 3 Long Range.

## Ajuste editorial de la landing

### Cambios aplicados

- La landing dejó de concentrar sus imágenes en el hero. Ahora el recorrido se narra en dos momentos visuales separados:
  1. **Hero de bienvenida:** vehículo eléctrico, camino y paisaje austral, con una animación breve de avance sobre una ruta.
  2. **Sección de viaje responsable:** una segunda imagen de parque y naturaleza aparece más abajo, junto a los pasos reales para planificar: elegir vehículo, trazar recorrido y revisar carga.
- Se reforzó el concepto de ruta sin inventar un trayecto: la landing muestra movimiento y orientación visual, pero el recorrido sólo se calcula al abrir **Mi ruta** e ingresar origen, destino y vehículo.
- Las vistas ahora también son rutas navegables en el navegador: `/` para la landing, `/ruta` para el planificador, `/ruta?tab=catalogo` para la red de carga, `/sesion` para la cuenta y `/administracion` para el panel restringido. Los botones del encabezado y los controles de la landing actualizan la URL y el historial del navegador.
- Se añadió una estructura editorial asimétrica, con tipografía de alto contraste, una progresión 01–03, CTA directo al planificador y panel de paisaje independiente. Esto evita el aspecto de una única tarjeta promocional y da continuidad al scroll.
- Las animaciones de vehículo y panorámica se desactivan cuando el sistema declara `prefers-reduced-motion`.

### ¿Qué problemas enfrentó?

- Las electrolineras inicialmente quedaban asociadas principalmente a una comuna, sin una dirección ni detalle técnico suficiente para tomar una decisión de viaje.
- Las fuentes abiertas entregan campos heterogéneos: distintas formas de escribir conectores, estaciones repetidas, datos técnicos incompletos y cambios de disponibilidad.
- Algunos modelos 3D genéricos no representaban fielmente a los vehículos del catálogo.
- El frontend presentó un error de referencia no definida en el encabezado (`Zap`), bloqueando el renderizado completo.

### ¿Cómo resolvió el problema?

- Incorporó un servicio de normalización para SEC / EcoCarga, con caché de dos minutos y procedencia explícita; no rellena datos técnicos que la fuente no informa.
- Normalizó conectores, consolidó estaciones equivalentes y preservó el último conjunto válido si falla una importación.
- Ajustó la interfaz para mostrar dirección, equipos, potencia, conectores, estado reportado y compatibilidad antes de sugerir una carga.
- Aplicó la regla `tieneModelo3D`: el visor aparece sólo para vehículos cuyo modelo 3D está validado.
- Corrigió la importación de `Zap` y validó que el build de Vite vuelve a compilar correctamente.
